   - 1.3 新增：「借閱數量上限」及「借閱期限」說明 — 系統管理者可調整設定學生及老師的借閱數量上限／借閱期限上限。

4. **安全性**
   - 備份方法建議有 2 種：
     1. 系統自動完整備份 — 原系統既有的完整 JSON 備份（管理者可設定自動系統備份時間）。
     2. 使用者手動操作資料備份（三份清單：圖書已借出清單／使用者清單／圖書清單；未來可匯入還原）。
   - 3.2 執行檔封裝要求：v2.0 曾要求「封裝為獨立之 .exe（如 Electron）或自帶微型伺服器…嚴禁 file://」；v2.1 內容只剩「自帶微型伺服器（以 http://localhost 運行）。嚴禁直接以 file:/// 協定開啟網頁。」→ **交付要求中的 Electron 選項被移除**。

5. **圖書館藏與財產管理**

6. **加快借還書速度**

   - 5.1 新增「緊急變通應用」：全園幼兒條碼名冊找不到／掃碼機故障時，可刷或輸入老師條碼，仍以「先選班級，再選成員」指定學生借還書。

## 二、v2.1 版本中「不合理或需要修正」的地方

### 1. 版本號與文件結構本身

- 「文件版本：v2.0」未更新，與檔案名 v2.1 不一致；目錄（七章節）未收錄「八、上線後交付文件」，與正文新增章節不符。

### 2. 用語與邏輯問題（含新增內容）

- **4.2 描述仍有誤**：仍說「系統目前只有在館、借出、修繕，卻沒有『狀態備註』欄位」；v2.1 狀態清單為「在館、借出、遺失、修繕中、爭議中」（另有報廢），「修繕中」已是狀態，措辭應改為「只有在館、借出、報廤…」或明確列出現有狀態。
- **2.1／1.6 的「帳務結清」vs「一鍵清楚借閱紀錄」**：前者指每學期末結清（還書／次數統計），後者指盤點後清除歷史紀錄，兩者目的可能重疊，需釐清是否可同時設定。
- **「借閱紀錄僅每學年有效…a01 即為閱讀紀錄」**：v2.1 在每學期末進行帳務結清，但仍保留「僅每學年有效」的週期設計，跨學年資料保留策略需確認。
- **5.1 緊急變通**：仍依賴「先選班級，再選成員」選單，未解決「全靠條碼槍、不用滑鼠」的目標。

### 3. v2.1 新增內容中的不合理或待商榷項目

- **3.2 交付要求變動**：移除 Electron 交付選項、僅保留微型伺服器 — 方向合理（與原系統一致），但變更來源不明（廠商或園方），應確認決策依據。
- **7.2 全園閱讀歷程統計**：「借閱人（可選擇老師或學生）／借閱總次數」跨年統計需求，與「僅每學年有效」的週期設計是否衝突，待確認。
- **8.1 功能確認單**：TABLE 8 內容（正常／異常／改善欄位）全為空白 — 交付文件本身不完整，需園方填寫。
- **借閱期限調整**：「系統管理者須能自由調整每學期開學日及還書到期日」— 原系統借閱期限無後端設定值，需新增。

### 4. v2.0 檢查中已列之問題，v2.1 未見消除

- 財產編號定義、Barcode 與財產編號之分、紀錄週期與爭議調查、還書條碼未定義等問題，v2.1 多數延續，未解決。

## 四、小結：v2.1 對上次檢查的補充意義

1. v2.1 新增「上線後交付文件」章節，要求功能確認單、操作手冊、安裝程式及程式碼交付 — 對原系統而言屬於「文件與交付流程」工作，非程式碼，但需確認 `server.py` 可交付（含 `--https`、`--db` 等參數）與安裝步驟文件。
2. v2.1 明文把「管理者可調整借閱數量上限／借閱期限」寫入需求，此前僅以數值呈現 → 原系統需補後端調整能力。
3. v2.1 將爭議查詢年份改為「115學年」，與附件九（學生名單，班代碼 A01–D24、F 班）對齊 → 借閱統計與學生編號（學號）的對應需在系統內；
4. v2.1 備註欄改為「自由填寫文字」，與「狀態備註」分工（狀態 vs 備註文字）需明確。
5. v2.1 移除 Electron 交付要求，與原系統「自帶微型伺服器」現行架構一致，此處**無需修改**，屬需求與系統方向的合理收斂。

### 對原系統的最終修改清單（依 v2.1 新進度）

- 必做（高優）：status 擴充（遺失／修繕中／爭議中＋不可借出）、備註欄、借閱上限／到期日管理、批次匯入、個人／全園閱讀統計（學號／員工編號）、一鍵清楚借閱紀錄、逾期功能、F06、報表格式。
- 交付面向：功能確認單、操作手冊、安裝程式交付文件（文件層面）。
