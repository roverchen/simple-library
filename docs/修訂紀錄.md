修訂紀錄
========

本文件記錄相對於原始版本的功能新增與問題修正。
對應規格文件：`幼兒園圖書管理系統功能彙整.pdf`（共 40 條）


一、功能新增
------------

### 資料備份與匯出（新增）
新增於「系統設定 → 資料備份與匯出」。

- **匯出完整備份** — 將館藏、成員、借閱紀錄、系統設定打包為單一 JSON 檔，
  檔名含日期時間（例：`圖書系統備份-20260116-1530.json`），
  匯出後顯示館藏／成員／紀錄筆數統計
- **匯入備份** — 驗證檔案格式後顯示即將載入的筆數，二次確認才覆蓋；
  **管理密碼不會被覆蓋**，避免匯入舊備份後遭鎖在門外
- **匯出借閱紀錄 CSV** — 含時間／班級／姓名／書名／財產編號／條碼／動作，
  前置 UTF-8 BOM 使 Excel 開啟時中文不亂碼，
  欄位自動處理逗號、引號、換行的跳脫

### 條碼槍輸入（補齊 README 所述功能）
原始版本的 README 宣稱支援條碼槍，但程式中並無實作。

借還書頁與圖書管理頁各新增條碼輸入框，監聽 Enter 鍵，
與相機掃描共用同一條處理流程（含借閱防呆、報廢攔截、去重）。

- 掃描後自動清空輸入框並重新對焦，可連續掃描
- 模式下拉選單與相機掃描共用，切換時同步更新
- 登入後、切換頁面、掃描結束時自動取得焦點
- 管理頁的輸入對話框關閉後，焦點自動還原

### 單本 QR 標籤列印預覽（PDF 第 34 條）
圖書管理頁面每列新增「🏷️ 標籤」按鈕，可單獨列印該書標籤。

- 列印時以 `body.printing-label` 隔離，只輸出標籤本身
- QR Code 放大至 200×200（單本不需三欄排版）
- 監聽 `afterprint` 自動清理暫存內容
- 報廢的書不提供此按鈕


### v2.1 客製化需求：多帳號、借閱規則、預約、批次操作與館藏查詢（新增）
依客製化需求清單 v2.1 逐項完成：

- **多帳號（需求 1.1）** — 新增 `users` 表（帳號、PBKDF2 密碼、角色、班級、啟用），
  `sessions` 綁定 `user_id`；`api_login` 支援帳號＋密碼登入，
  未填帳號時以管理密碼備援登入為系統管理員。
- **借閱上限／期限（需求 1.3）** — `settings` 新增 `loan_limit_student`／`loan_limit_teacher`、
  `loan_days_student`／`loan_days_teacher`；借書依角色套用上限並設定 `books.due_at` 到期日。
- **逾期（需求 1.4）** — 新增 `GET /api/report/overdue`，列出已過期的借出。
- **索書號（需求 4.5）** — `books.call_no`；圖書編輯與館藏查詢均會回傳索書號。
- **館藏查詢（F06）** — 新增 `GET /api/books/search`，支援關鍵字查詢
  （書名／財產編號／條碼／ISBN／備註）。
- **預約（需求 4.4）** — 新增 `reservations` 表（pending / cancelled / fulfilled）與
  `POST /api/reservations`、`GET /api/reservations`、`POST /api/reservations/{id}/cancel`；
  借書成功時自動履約該成員的預約。
- **批次還書（加快借還速度）** — 新增 `POST /api/loan/batch-return`，一次輸入多組條碼（以逗號、空白或換行分隔）逐筆還書。
- **指令條碼（5.2）** — 掃描流程支援 `borrow:<條碼>`／`return:<條碼>` 功能指令 QR；前端新增指令 QR 產生（`generateCommandQR`）。
- **自動完整備份（需求 3.1）** — 後端排程每日自動備份至 `data/backups/`（保留 7 檔），
  並提供手動 `POST /api/backup/run` 與匯出端點。
- **密碼自救（3.3）** — 新增公開端點 `POST /api/password/reset`（提供目前管理密碼與新密碼，驗證通過後更新並全端失效）。
- **學年週期與全園統計（2.1）** — `GET /api/logs` 新增 `schoolYear` 篩選（民國年，例如 115 = 2026/08/01～2027/07/31）；新增 `GET /api/report/stats` 提供全園／班級／成員借書次數統計；報表頁新增學年篩選與全園閱讀歷程統計。
- **索書號條碼列印（7.2）** — 報表頁「標籤模式」新增「索書號條碼（Code 128）」選項，以純前端方式繪製 Code 128B 條碼，免外部套件；未填索書號或含不支援字元的書籍會自動略過並顯示摘要。
- **財產清冊／報廢清冊列印（7.2）** — 報表頁新增「清冊列印」，可輸出 A4 表格（財產編號、書名、索書號、狀態、借閱人、備註）；財產清冊排除報廢書，報廢清冊僅列報廢書。
- **其餘報表列印（7.2）** — 新增已借出清單、爭議／遺失／修繕清冊、個人閱讀歷程統計（可選班級、姓名、學年）；全園統計、逾期清單與借閱紀錄亦可直接列印或下載 PDF。
- **PDF 報表匯出（7.1）** — 新增 `pdf_report.py`（只用 Python 標準函式庫），內嵌 `vendor/NotoSansTC-Regular-subset.ttf`（SIL OFL 授權）產生中文 PDF；提供 `/api/report/*.pdf` 端點（借閱紀錄、財產／報廢清冊、已借出、爭議清冊、逾期、個人／全園統計），支援自動換頁與頁碼。
- **狀態擴充（需求 4.1）** — `books.status` CHECK 擴充「遺失、修繕中、爭議中、報廢」，並保留 `remarks` 備註欄位。

### 115 學年正式資料匯入與借閱期限修正（2026/10/31）

- 匯入 115 學年正式名冊與館藏：6 個幼兒班、123 位幼兒、19 位教職員、1,466 本圖書；
  匯入結果與異常處理詳見 `docs/資料匯入結果_115學年.md`。

- `GET /api/state` 的館藏資料補上 `loanClass`、`dueAt`，已借出清冊與畫面可正確顯示班級與應還日期。

### 預約功能修正（2026/10/31）

- 修正報廢書仍可被預約的錯字問題（`報廤` → `報廢`）。
- 限制只有「借出中」的書可以預約；在館書籍直接借閱即可，系統會回覆「無需預約」。
- 過期預約會自動取消，不再出現在「進行中預約」清單，清單同時顯示有效期限。
- 條碼槍模式新增「📌 預約」，掃描 Enter 只建立預約，不會誤觸借書／還書。


### ISBN 欄位（2026/10/31）

- `books` 新增 `isbn` 欄位，與「索書號（call_no）」分開：索書號用於排架，ISBN 用於辨識版本。
- 圖書編輯（桌機／手機）可輸入 ISBN；圖書列表與館藏查詢同步顯示。
- 館藏查詢支援以 ISBN 搜尋。
- 圖書批次匯入支援第 5 欄 ISBN（選填），JSON 匯入支援 `isbn` 欄位；完整備份匯出／匯入也會保留 ISBN。


二、問題修正
------------

### 掃描流程
- **相機不再於可恢復的錯誤後自動關閉。** 原本重複借閱或重複歸還時會直接關閉
  相機，連續掃描必須重新開啟。現改為以畫面提示取代，相機保持開啟。
- **補上條碼去重。** html5-qrcode 於 20fps 下每個影格都會回報同一條碼。
  原本靠「掃完即關相機」意外掩蓋此問題；改為連續掃描後若不處理，
  同一本書會被重複處理十餘次。新增 1.5 秒去重視窗。
- **移除阻斷式 alert。** 原本每次掃描結果都跳 alert，會暫停 JavaScript 執行緒
  使相機完全停擋。改為畫面色塊提示，2.5 秒自動消失。
- **掃描模式標題顯示錯誤。** `#scanModeTitle` 被 `.scanning-active h3` 規則誤隱藏，
  且從未被設定內容。現已正確顯示三種模式，並調整 CSS 排除誤傷。
- **相機停止失敗時畫面卡住。** `stopScanner()` 在掃描器為 null 時直接返回，
  導致畫面停留在「掃描中」。現改為無論成功與否都執行清理。
- **相機啟動失敗訊息過於簡略。** 原本僅顯示「相機啟動失敗」，
  現列出三項可能原因，包含 `file://` 會被瀏覽器阻擋此常見情況。
- **掃描器重複啟動的競態。** 原本 `clear()` 後立即建立新實例，
  可能與尚未停止的舊實例衝突。改為等待完全停止後再啟動。

### 報廢與資料完整性
- **`mobile.html` 的「報廢」按鈕實際上是永久刪除。** 按鍵標示為報廢，
  實際執行 `delete bookDatabase[isbn]`，違反規格第 20 條要求的
  報廢→刪除階層，且資料不可復原。已改為狀態變更並新增「取消報廢」。
- **兩檔資料結構不相容。** `mobile.html` 寫入的館藏缺少 `loanedTo` 欄位，
  狀態字串格式亦不同（`借出 (姓名)` vs `借出(姓名)`），
  與 `index.html` 共用同一份資料時會互相污染。已統一格式，
  並在載入時執行正規化，從既有 status 字串回推借閱人，
  舊資料不需重跑即可修正。
- **報廢書的借閱狀態殘留。** 還書與復原時未確實清除 `loanedTo`。

### 報表
- **逾期報表路徑錯誤。** 前端呼叫 `/api/reports/overdue`（多 s），與後端
  `/api/report/overdue` 不一致，導致逾期清單載入失敗；已統一為單數路徑。

### 列印
- **列印會輸出全部頁面。** `@media print` 的 `.page { display: block !important }`
  會強制顯示所有頁面，導致列印時連登入畫面、班級成員、設定頁一併印出。
  改為僅輸出當前頁面。
- **列印時殘留掃描提示與掃描框。** 已加入隱藏規則。

### 效能
- **每次借還都重繪整份報表。** `processLoan` 無條件呼叫 `renderReportTable()`，
  但掃描時報表頁不可能是前景畫面，此呼叫為百分之百無用功。已加入條件判斷。
- **報表一次渲染全部紀錄。** 新增分頁，每頁上限 100 筆，
  單次渲染量由 O(全部紀錄) 降為固定上限。

### 介面
- **表格操作按鈕無樣式。** `btn-action` 系列類別（編輯／報廢／復原／刪除）
  在 `index.html` 中被使用但從未定義樣式，呈現為瀏覽器預設外觀。已補齊配色。
- **掃描結果提示位置。** 原置於相機框內，條碼槍模式下不可見。
  已移至容器層，兩種模式共用同一提示位置。


三、安全性
----------

- **內插資料未轉義。** 所有使用者輸入（書名、姓名、班級、條碼、財編）直接
  寫入 `innerHTML`。以 `<img src=x onerror=...>` 作為書名即會被解析為
  真實 DOM 元素並執行。已新增 `escapeHtml()` 並套用至全部渲染函式。
- **`onclick` 屬性內嵌資料。** 原本以 `onclick="deleteMember('${c}','${m}')"`
  傳遞資料，姓名含單引號即會使整段程式碼損毀，且構成注入路徑。
  已改為 `data-*` 屬性搭配事件委派。


四、開發過程中發現的自身錯誤
----------------------------

- 新增報表分頁時將函式插入於舊版 `renderReportTable` 之前，
  形成兩個同名函式。由於函式提升會讓後者覆蓋前者，
  分頁功能實際為死碼，且上一項的轉義修正被未轉義的舊版覆蓋。
  已移除重複宣告，並於驗證流程加入重複宣告檢查以防重演。

六、尚未處理的限制
------------------

以下為已知且刻意保留的限制，非缺陷：

- **單一共用密碼** — 沒有多位老師各自的帳號、角色或操作稽核。（後續 v2.1 已補多帳號與角色。）
  密碼已改為伺服器端 PBKDF2 雜湊驗證，不再能從瀏覽器原始碼繞過，
  但仍屬於「信任環境共用一組密碼」的設計。
- **預設密碼 `1234` 已載於規格 PDF** — 正式使用前務必修改。
- **相機需要安全內容** — 區網以 `http://IP` 開啟時相機會被瀏覽器封鎖，
  需改用條碼槍或 HTTPS。
- **借閱紀錄無法依日期篩選** — 資料表已保留 `created_at`，
  但目前介面只提供分頁與 CSV 匯出。（後續 v2.1 已補年度／學年篩選。）
- **單一伺服器** — 沒有內建備援或即時複寫；請定期備份 `data/library.db`
  或使用系統內的 JSON 備份。
- **手機版功能較少** — 不含班級成員管理與標籤列印。


七、離線化與資料庫後端（v2）
----------------------------

### 前端離線化
- `html5-qrcode` 與 `qrcodejs` 改由 `vendor/` 載入，不再連線 unpkg / cdnjs。
- 無網際網路環境下仍可掃碼與列印標籤。

### SQLite 後端
- 新增 `server.py`（僅 Python 標準函式庫）與 `schema.sql`。
- 資料由瀏覽器 localStorage 改為 `data/library.db`；多台電腦連同一台
  伺服器即可共用。
- 密碼改存 PBKDF2 雜湊；登入使用 12 小時的 HttpOnly 工作階段 Cookie。
- 借還改為伺服器端交易（`BEGIN IMMEDIATE`），避免兩台同時借出同一本書。
- 報表改由後端分頁，CSV 由後端產生，不再把全部紀錄載入瀏覽器。
- 新增 `GET /api/session`，未登入時不再產生 401 錯誤。
- 第一次登入若偵測到舊 localStorage 資料，會詢問並匯入資料庫。
- 舊備份 JSON（含 `status: "借出(姓名)"` 格式）可直接匯入。

### 相容性
- `index.html` / `mobile.html` 仍維持原本的 `bookDB`、`memberDB`、
  `libConfig` 欄位格式，降低改寫風險。
- 備份檔版本提升為 2，仍可讀取版本 1 的資料。
