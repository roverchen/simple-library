## 一、需求 → 原系統修改清單對照表

依 v2.1 文件段落（1.1–1.6、2.1–2.2、3.1–3.3、4.1–4.5、5.1–5.3、6、7.1–7.2、8）逐項對照，列出需要修改的原系統位置。

### 一、（一）權限分級與多帳號管理

| v2.1 需求 | 原系統現況 | 需修改的檔案／位置 |
|---|---|---|
| 1.1 系統 Root（備用）＋系統管理員（日常）＋一般使用者（老師／學生） | `settings.admin_password` 單一共用密碼；`sessions` 只有 token（無帳號綁定）；無角色概念 | `schema.sql`：`users` 表（角色、啟用狀態）；`server.py`：`api_login`、`api_logout`、`api_password`、`sessions` 改綁定 user；`index.html`／`mobile.html` 登入 UI、後台授權檢查 |
| 1.3 管理者可調整借閱數量上限／借閱期限上限 | `api_loan` 未寫上限與到期日；`schema.sql` `books` 無借閱上限／到期欄位；無「開學日」設定 | `schema.sql`：`books` 加 `loan_limit`、`due_at`（或 settings 表加 keys）；`server.py`：`api_loan` 寫入借出資訊、檢核期限與上限；新增 settings 更新 API；前端系統設定頁 |
| 1.4 逾期提醒及報表（逾期未還清單，管理者） | 完全沒有逾期概念 | `schema.sql`：`books` 加 `due_at`；`server.py` 新增逾期計算與 `/api/reports/overdue`；前端「報表/列印」新增逾期清單 |

### （二）學籍批次處理與「學期轉換／升級」機制

| v2.1 需求 | 原系統現況 | 需修改的檔案／位置 |
|---|---|---|
| 2.1 批次匯入功能（老師／學生名單，Excel/CSV；欄位 mapping：姓名、班級、學號） | `api_classes`、`api_member_add`、`api_member_delete` 為單筆；無批次匯入 | `server.py` 新增 `POST /api/members/import`（CSV）；`server.py` 如需批次匯入圖書則加 `POST /api/books/import`；`index.html`／`mobile.html` 新增上傳介面與欄位對應選單（2.2 mapping UI） |
| 2.1 學年週期（閱讀紀錄僅每學年有效；每學期末帳務結清；爭議/遺失狀態記錄到書籍狀態追蹤） | `loan_logs` 無年份欄；無學年參數；狀態不可自由改 | `schema.sql`：`loan_logs` 加 `year`（或由班級／成員推導）；`server.py` 統計與匯出時依學年分；狀態流轉支援「爭議／遺失」 |

### （三）安全性：資料庫、雲端備份、程式開啟、密碼自救機制

| v2.1 需求 | 原系統現況 | 需修改的檔案／位置 |
|---|---|---|
| 3.1 系統自動完整備份（JSON，管理者可設自動備份時間）＋使用者手動三份清單備份／匯入 | `GET /api/backup`、`POST /api/import` 已存在（完整 JSON）；無定時自動備份、無雲端、無 10 天循環覆蓋 | `server.py` 新增定時備份 task（每日自動輸出＋保留 10 天循環覆蓋）；備份內容需含「圖書已借出清單／使用者清單／圖書清單」或維持完整 JSON；還原機制 |
| 3.2 執行檔封裝要求 | 原系統已符合（自帶微型伺服器 + 嚴禁 file://） | **無需修改**（v2.1 與原系統方向一致） |
| 3.3 密碼自救（離線安全提問／雙軌制 系統管理員＋系統 Root） | 僅單一密碼改 PBKDF2；無重置流程 | `server.py` 新增密碼重置端點（安全提問或雙帳號驗證）；前端忘記密碼頁 |

### （四）圖書館藏與財產管理

| v2.1 需求 | 原系統現況 | 需修改的檔案／位置 |
|---|---|---|
| 4.1 財產編號（Asset_id）唯一；當狀態為「遺失、修繕中、爭議中」則不可借出 | `books` 有 `barcode` PK、`asset_id`、`status` CHECK（僅「在館／借出／報廤」） | `schema.sql`：`status` CHECK 擴充為「在館、借出、遺失、修繕中、爭議中、報廤」；`server.py`：`api_loan` 拒借上述狀態；`api_book_upsert` 可改狀態 |
| 4.2 備註欄位（自由填寫文字，瑕疵與缺件） | `books` 無 remarks；`api_book_upsert` 未收 remarks | `schema.sql`：`books` 加 `remarks`；`server.py`：`api_book_upsert` 寫 remarks；`index.html` 編輯 UI |
| 4.4 預約功能（借出時提供預約排隊，先開發、暫時不開啟） | 無 | 新增 `reservations` 表 + API + 借書流程整合 |
| 4.5 索書號（主分類色＋次分類＝書名首字注音；可自動產生、可手改） | `books` 無 `call_no` | `schema.sql`：`books` 加 `call_no`；`server.py` 自動產生；前端建檔介面輸入類別＋自動產生 |

## 二、修改優先順序建議（依 v2.1 需求新舊與重要性）

1. **最高**：`schema.sql` + `server.py` — status 擴充（遺失／修繕中／爭議中）、備註欄、索書號欄位、借閱上限／到期日、逾期。
2. **高**：`server.py` + 前端 — 多帳號／密碼自救、批次匯入、自動備份、F06、個人統計。
3. **中**：`index.html`/`mobile.html` — 成員條碼與名冊列印、指令條碼、批次還書、預約、借還流程改「刷碼」。
4. **中低**：`server.py` — xlsx/pdf 報表、全園統計、爭議記錄報表。
5. **低／文件**：交付文件（功能確認單、操作手冊、安裝程式）。
